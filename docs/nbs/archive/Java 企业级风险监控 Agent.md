# 第一章 项目概述

## 1.1 项目背景

企业 Java 系统通常由多个业务系统和基础设施组件组成。业务系统运行过程中会产生大量交易、登录、接口调用和系统运行数据。

传统监控通常关注 CPU、内存、连接数、响应时间等基础设施指标，难以直接识别客户交易行为异常、账号攻击、接口滥用等业务风险。

本项目希望利用 DSH Agent Runtime 构建统一的风险监控 Agent，将业务风险监控、系统指标监控、风险判定、风险证据、处置建议、通知和报告整合到一个模块化插件中。

项目采用 Agent-first 设计，不建设额外的 Web 管理平台，也不建设独立 Java 风险平台。

## 1.2 项目建设目标

V1 建设目标如下：

1. 采集企业 Java 项目相关业务数据和系统运行指标。
2. 建立统一的 Metric 指标定义和计算能力。
3. 建立声明式 Rule 规则判定引擎。
4. 建立统一 Risk Event 和 Risk Cycle 管理机制。
5. 对风险判定生成可追溯 Evidence。
6. 根据风险生成 Action Proposal。
7. 根据策略发送风险通知。
8. 提供业务风险报告和系统运行报告。
9. 提供监控覆盖率、运行诊断和 Runtime Alert。
10. 支持多租户、安全隔离、可靠持久化、备份和恢复。
11. 通过 DSH 原生 Tool 机制向 Agent 暴露业务能力。

## 1.3 V1 核心业务场景

V1 确定三个核心业务风险场景：

| 编号   | 业务场景                   | 核心目标                             |
| ------ | -------------------------- | ------------------------------------ |
| BR-001 | 客户日交易金额异常         | 识别客户或账户交易金额异常           |
| BR-002 | 客户登录失败异常           | 识别暴力破解、撞库和异常登录         |
| BR-003 | API 调用频率与接口滥用风险 | 识别异常调用、接口滥用和异常调用序列 |

此外，V1 同时建设系统运行指标监控，覆盖八类技术组件。

## 1.4 项目总体原则

- DSH 是底层 Agent Runtime。
- V1 采用单 Agent、单进程、单插件、单实例。
- V1 不使用 Kafka。
- V1 不建设 Web UI。
- V1 不建设独立 Java 风险平台。
- V1 直接使用 DSH 原生 Tool Registry。
- V1 只生成 Action Proposal，不执行真实拦截、封禁、限流等操作。
- 配置以 YAML 为主。
- 持久化以 JSON 为主。
- 报告支持 JSON 和 Markdown。
- 采用模块化设计，预留后续扩展能力。

# 第四章 BR-001 客户日交易金额异常

## 4.1 业务目标

识别客户或账户在指定统计周期内的交易金额异常，支持固定阈值、动态阈值、历史基线和多等级风险判定。

## 4.2 统计主体

支持：

- 客户。
- 账户。

由 Metric Definition 决定聚合主体。

## 4.3 交易数据口径

默认只统计 SUCCESS 状态。

其他业务状态通过状态映射配置处理。

默认采用交易实际成功时间，允许配置其他时间字段。

支持：

- 原始交易金额。
- 扣除退款、冲正后的净金额。
- 多币种分别统计。
- 明确汇率来源后进行统一换算。

异常金额数据必须标记 INVALID，不得静默转换成零。

## 4.4 统计窗口

支持：

- 自然日。
- 滚动 24 小时。

默认自然日，按租户时区计算。

## 4.5 阈值和规则

支持：

- 固定金额阈值。
- 动态客户属性阈值。
- 多金额区间。
- 多风险等级。
- 多 Rule 组合。
- 多个 Action Proposal。

规则支持大于、大于等于、小于、小于等于和等于等比较操作。

## 4.6 风险生命周期

- 事件触发检测和定时检测。
- 同一风险周期维护主风险事件。
- 检测结果变化追加历史。
- 支持迟到交易触发历史窗口重算。
- 历史重算保留原结果和修正记录。
- 支持恢复阈值、连续检测次数和持续时间。
- 统计周期和风险周期分离。
- 客户合并、拆分保留原主体快照。

## 4.7 数据质量

数据质量包括：

- NORMAL。
- STALE。
- PARTIAL。
- ERROR。
- INVALID。

数据质量异常不得直接判定风险恢复。

## 4.8 证据和处置建议

Evidence 至少包含：

- Metric Snapshot。
- 阈值。
- Rule Version。
- 统计窗口。
- 交易引用。
- Data Quality。
- 判定时间。
- 判定依据。

Action Proposal 根据风险等级、客户属性和规则条件生成。

V1 不执行真实业务动作。

## 4.9 验收要求

BR-001 必须覆盖：

- 正常交易统计。
- 交易状态过滤。
- 退款和冲正。
- 多币种。
- 自然日和滚动窗口。
- 动态阈值。
- 多风险等级。
- 迟到数据。
- 历史重算。
- 重复采集。
- 数据质量异常。
- 风险恢复。
- 主体合并和拆分。
- Evidence。
- Proposal。
- 通知。
- 多租户隔离。

详细 AT-001～AT-020 验收用例应作为独立测试附件维护。

# 第五章 BR-002 客户登录失败异常

## 5.1 业务目标

识别异常登录失败、暴力破解、撞库、分布式攻击和异常认证行为。

## 5.2 统计维度

支持：

- 客户。
- 账号。
- IP。
- 设备。
- 多维组合。

## 5.3 登录结果口径

登录失败类型由配置决定是否计入。

系统内部错误和网络故障不默认视为客户认证失败。

支持：

- 固定窗口。
- 滚动窗口。
- 成功后清零。
- 自然过期。
- 时间衰减。

默认使用认证完成时间，同时保留 eventTime 和 collectedAt。

## 5.4 IP 与主体识别

真实客户端 IP 必须基于可信代理列表判断。

不得无条件信任 X-Forwarded-For。

共享 IP、可信 IP 白名单和共享出口策略必须纳入分析。

相同 IP 或设备不能直接证明多个请求来自同一个人。

主体关联应保留依据、可信度和有效时间。

## 5.5 攻击识别

支持：

- 固定和动态失败次数阈值。
- 失败比例。
- 多账号失败。
- 多客户失败。
- 撞库分析。
- 分布式暴力破解。
- IP、设备、地域分析。
- 登录成功后的重新评估。
- 失败分类统计。

登录成功不能自动清除历史风险。

## 5.6 风险事件与攻击事件

主体级风险事件和关联攻击事件分别管理。

持续攻击追加：

- 风险等级变化。
- 攻击规模变化。
- 受影响对象变化。
- 关联主体变化。

恢复后再次攻击创建新的 Risk Cycle，并关联历史事件。

## 5.7 Proposal

支持建议类型：

- 预警。
- 通知。
- 人工审核。
- 账号锁定。
- IP 封禁。
- 设备限制。
- 强制 MFA。

以上均为建议，V1 不实际执行。

## 5.8 安全和证据

Evidence 包含登录事件引用、统计窗口、失败分布、IP/设备关联、规则版本、质量状态、攻击事件和判定依据。

禁止记录：

- 密码。
- 验证码。
- Token。
- Cookie。
- 其他敏感认证凭据。

默认严格租户隔离。

跨租户威胁关联必须经过显式授权和脱敏。

## 5.9 验收要求

覆盖：

- 登录结果分类。
- 时间窗口。
- 成功后清零。
- 多维度组合。
- IP 可信代理判断。
- 事件去重。
- 撞库识别。
- 分布式攻击。
- 主体关联可信度。
- 登录成功重新评估。
- 风险周期恢复。
- 敏感信息保护。
- 跨租户隔离。
- Evidence。
- Proposal。
- 通知和审计。

# 第六章 BR-003 API 调用频率与接口滥用风险

## 6.1 业务目标

识别异常 API 调用频率、接口滥用、异常调用序列和多主体协同攻击。

## 6.2 统计维度

支持：

- API。
- 客户。
- 账号。
- IP。
- 设备。
- 渠道。
- 多维组合。

## 6.3 请求阶段

支持：

- 请求到达。
- 鉴权通过。
- 业务处理开始。
- 业务处理完成。

具体阶段由 Metric 配置决定。

支持：

- 总调用数。

- 失败数。
- 成功率。
- 失败率。
- 平均响应耗时。
- 最大响应耗时。
- P50、P90、P95、P99。

- API 数量和类别分布。
- 首次访问。
- 历史未访问 API。
- 关键参数分布。
- 业务对象访问数量和序列。

敏感字段必须使用白名单控制，不采集密码、Token 和 Cookie。

## 6.5 时间和行为分析

支持：

- 允许调用时间段。
- 历史访问规律。
- 分时段基线。
- 工作日差异。
- 主体行为偏离。
- API 调用序列。
- 调用顺序。
- 调用间隔。
- 业务操作组合。
- 异常业务流程。

## 6.6 基线和 Rule

支持固定阈值、历史均值、移动平均、分时段基线和偏离比例。

防止异常数据污染基线。

Rule DSL 支持 AND、OR、NOT、嵌套条件、阈值区间和时间窗口。

阈值可按 API、API 类别、客户等级、账号类型和渠道配置。

支持优先级和继承。

## 6.7 风险和 Proposal

风险评分综合阈值、基线偏离和业务敏感度。

Risk Event 按主体、API、攻击模式和风险周期聚合。

关联攻击事件独立管理。

Proposal 可建议：

- 预警。
- 通知。
- 人工审核。
- 限流。
- IP 封禁。
- 账号限制。
- 设备限制。
- 接口暂停。
- 强制二次认证。

V1 不执行真实动作。

## 6.8 恢复和证据

支持恢复阈值、连续检测、持续正常时间、攻击停止和人工确认。

Evidence 保存统计窗口、调用次数、成功失败分布、响应耗时、API 分布、主体关联、调用序列、基线、规则版本、数据质量和判定依据。

## 6.9 验收要求

覆盖采集、多源关联、参数白名单、调用序列、基线、迟到数据、去重、数据质量、通知、多租户、证据和 Proposal 生命周期。

# 第七章 Metric 指标模型

## 7.1 Metric 定义

Metric 统一包含：

1. Metric Definition。
2. Data Source。
3. Dimensions。
4. Aggregation。
5. Data Quality。
6. Metric Result / Metric Snapshot。

Metric 类型：

- COUNTER。
- GAUGE。
- RATE。
- RATIO。
- DISTRIBUTION。
- DERIVED。

## 7.2 Metric Definition 与 Result

Metric Definition 与 Metric Result 必须分离。

Metric Definition 版本化。

历史 Metric Result 保留原版本。

修改定义后，新的计算使用新版本。

历史重算产生新结果版本，不覆盖原始结果。

## 7.3 派生指标

支持：

- 依赖 DAG。
- 四则运算。
- 条件表达式。
- 受控函数。
- 多级派生。
- 循环依赖检测。

禁止任意 JavaScript 和动态代码执行。

## 7.4 维度与基数

支持维度集合、组合模板和 Rule 选择合法组合。

高基数治理应覆盖全局、租户、Metric 和维度组合。

支持 Top-K、低频归并、白名单、拒绝和资源预算。

不能静默隐藏关键风险对象。

## 7.5 Metric Engine

Data Source Adapter 负责采集和标准化。

统一 Metric Engine 负责：

- 数据过滤。
- 维度提取。
- 聚合。
- 派生。
- 数据质量判断。
- 结果版本管理。

特殊数据源允许使用专用计算 Adapter。

## 7.6 Metric Result 字段

至少包含：

- tenantId。
- metricId。
- metricVersion。
- dimensionValues。
- windowStart。
- windowEnd。
- eventTimeWatermark。
- value。
- unit。
- dataQuality。
- calculatedAt。
- sourceReferences。

## 7.7 Metric Snapshot

Metric Snapshot 在风险判定引用时保存。

Snapshot 不可覆盖，必须能够追溯原始 Metric Version 和计算窗口。

# 第八章 Rule DSL 统一规则引擎

## 8.1 基本原则

Rule 采用声明式 DSL。

Rule 不直接采集数据，而是通过 Metric Binding 获取指标。

不允许 LLM 自由生成任意可执行代码。

## 8.2 Metric Binding

每个 Binding 支持声明：

- Metric。
- 维度。
- 时间窗口。
- 过滤条件。
- 主体关联关系。
- 数据质量要求。

## 8.3 执行模式

支持：

- Event。
- Scheduled。
- Manual。

三种执行方式统一进入 Rule Evaluation 流程。

触发去重和计算去重分别治理。

## 8.4 主体和时间范围

支持租户范围、主体类型、主体筛选、Metric 维度组合和动态主体发现。

不同 Metric 时间窗口支持：

- 时间对齐。
- 窗口交集。
- 结束时间对齐。
- 时间偏差。
- 数据新鲜度要求。

不满足数据要求时不能强行判定。

## 8.5 评估状态

支持：

- TRUE。
- FALSE。
- UNKNOWN。
- ERROR。

UNKNOWN 不等于 FALSE，也不代表风险恢复。

## 8.6 时间状态与多阶段规则

支持：

- 连续命中次数。
- 持续时间。
- 累计次数。
- 窗口命中次数。
- 时间衰减。
- 多阶段状态机。
- 超时。
- 退出条件。
- 阶段性风险等级。

Rule 状态机不替代 Application Workflow。

## 8.7 风险评分

支持权重、条件评分、封顶、扣分、评分区间和因子贡献记录。

评分必须确定性计算。

LLM 不得自由给出最终风险分数。

## 8.8 规则冲突和版本

支持：

- 优先级。
- 分组。
- 互斥。
- 合并策略。
- 风险等级聚合。
- Proposal 去重。

每次 Evaluation 固定 Rule Version。

历史重算必须指定规则版本。

## 8.9 Rule Evaluation Result

必须保存：

- Rule ID。
- Rule Version。
- Tenant。
- Subject。
- Metric 引用。
- 条件明细。
- 风险等级。
- 评分。
- Data Quality。
- 评估时间。
- 不可判定原因。

支持人工重新评估，保留原结果及差异。

# 第九章 Risk Domain 风险事件模型

## 9.1 核心对象

建议核心对象：

- RiskEvent。
- RiskCycle。
- RiskEventHistory。
- RiskRelation。
- RiskEvidenceReference。
- RiskImpactScope。
- RiskEvaluationReference。
- RiskSuppression。

## 9.2 Event 和 Cycle

Risk Event 表示稳定风险身份。

Risk Cycle 表示一次独立的风险发生周期。

风险恢复后关闭当前 Cycle。

再次异常时创建新的 Cycle。

根据身份策略复用 Risk Event 或创建新的 Event，并保留历史关联。

## 9.3 事件聚合

稳定身份考虑：

- Tenant。
- Subject Type。
- Subject ID。
- Risk Category。
- Risk Scenario。
- Risk Cycle。

多个 Rule Evaluation 可以关联同一事件，但不能删除各自命中的事实。

## 9.4 风险等级和状态

风险等级与生命周期状态分离。

统一严重程度字典：

- INFO。
- LOW。
- MEDIUM。
- HIGH。
- CRITICAL。

各领域保留独立评分和判定策略。

等级映射统一，用于通知、报告和查询。

## 9.5 关联关系

支持：

- RELATED_TO。
- CAUSED_BY。
- TRIGGERED_BY。
- AFFECTS。
- PART_OF。
- DUPLICATE_OF。

关联关系保存方向、依据、可信度、有效时间和来源。

自动关联与人工关联必须能够区分。

## 9.6 人工处置

支持：

- 确认误报。
- 接受风险。
- 确认真实风险。
- 要求进一步调查。
- 人工关闭。
- 重新打开风险周期。

人工处置与自动判定事实分离。

人工操作必须记录操作者、原因、时间和审批信息。

## 9.7 风险恢复

恢复条件支持：

- 恢复阈值。
- 连续检测次数。
- 持续时间。
- 异常停止。
- 数据质量。
- 人工确认。
- AND/OR 组合。

UNKNOWN、ERROR、STALE、PARTIAL 不得直接触发恢复。

## 9.8 人工临时风险干预

支持：

- 临时重点关注主体。
- 临时风险抑制或例外。
- 人工调整监控优先级。
- 指定有效期。
- 原因、操作者和审批要求。
- 到期自动失效。

人工干预不能篡改历史 Evaluation 和 Risk Event。

# 第十章 Evidence 证据管理

Evidence 必须引用不可变判定快照。

引用内容包括：

- Risk Event。
- Risk Cycle。
- Rule Evaluation。
- Metric Result。
- Rule Version。
- 配置版本。
- 判定时间。
- 数据质量。

Evidence 生成失败不能阻断 Risk Event 核心事实保存。

Evidence 独立管理状态、重试、归档和保留策略。

完整性支持 SHA-256、版本追踪和校验。

摘要不等于绝对不可篡改；重要证据可使用受控密钥签名。

抑制不等于风险恢复。

# 第十九章 安全要求

## 19.1 身份与授权

分层授权：

- Plugin/Tool 入口。
- Application 业务授权。
- Domain 不变量。
- Infrastructure 文件、网络、SSH 和 Secret 访问。

默认拒绝。

## 19.2 Secret

YAML 只存 Secret Reference。

支持环境变量和受控本地 Secret Store。

明文不得进入日志、报告、备份和审计。

## 19.3 SSH

使用专用最小权限账号。

禁止默认 root。

命令白名单、参数校验、目标限制、超时、输出限制和执行审计必须落实。

## 19.4 SQL

使用只读账号。

表和字段白名单。

参数化 SQL。

禁止 LLM 自由拼接 SQL。

设置超时、分页、并发和结果限制。

## 19.5 安全审计

安全审计追加式保存。

支持完整性检查和受控签名。

安全事件独立建模。

支持凭据泄露、越权、审计篡改、配置异常等事件的响应流程。

## 19.6 数据导出

导出必须执行：

- 权限过滤。
- 字段脱敏。
- 资源限制。
- 高风险审批。
- 元数据记录。
- 有效期。
- 重新鉴权。
- 审计。
